PROJECT / 03 · 2025

POSTIT — Collaborative Digital Bulletin Board

POSTIT brings board-based sharing and conversation into one browser application. People can create boards, configure their appearance and visibility, publish posts with optional media, and respond through comments and reactions.

This case study is based on the supplied PHP source and SQL schema. No hosted project or source repository link was included, so “View Project” opens this verified project detail rather than claiming a live deployment.

01 / PRODUCT CAPABILITIES

A board, built for sharing.

Capabilities confirmed in the inspected application and schema.

01
Customizable boards

Set a title and description, choose public, private, or shared visibility, and select grid, list, or masonry layout. Board records also support background image/color and post-limit settings.

02
Posts and media

Text posts accept MIME-checked image (JPEG/PNG/GIF), MP4 video, or PDF uploads; PDFs are stored as document media. The schema lists “link” too, but no reviewed handler creates link media. Posts also support background color and ordering.

03
Comments

Users can add comments to posts. The SQL declares a parent_id self-reference, but reviewed comment handlers do not use it; nested replies are not claimed as an implemented feature.

04
Reactions

Record a user's post reaction using the schema's like, heart, or star values, with one reaction of each type per user and post.

05
Pin and organize

Posts store a pinned state and order index, updated by the reviewed post-pin and ordering handlers. The comment schema has no pin state, so comment pinning is not claimed.

06
Accounts and collaborators

Registration, login, and profile pages are present. Boards store an owner and a collaborator join table with Viewer, Contributor, and Moderator role values.

Access-control scope: role values exist in the schema, but the reviewed code does not apply role checks consistently to every mutation. This case study does not claim a fully enforced permission hierarchy. Admin PHP pages were excluded because their database queries do not match the supplied schema.

03 / DATABASE DESIGN

A six-table relational model.

Primary keys, foreign keys, and the main relationship paths from the supplied SQL.

  • OWNSTBL_POSTIT.user_id → TBL_Users.user_id
  • CONTAINSTBL_POSTS.postit_id → TBL_POSTIT.postit_id
  • AUTHORSTBL_POSTS.user_id → TBL_Users.user_id
  • HAS COMMENTSTBL_Comment.post_id → TBL_POSTS.post_id
  • COMMENT AUTHORTBL_Comment.user_id → TBL_Users.user_id
  • SELF FKTBL_Comment.parent_id → TBL_Comment.comment_id (declared in SQL)
  • BOARD MEMBERSTBL_Collaborators.postit_id / user_id / added_by → boards and users
  • REACTIONSTBL_Reactions.post_id / user_id → posts and users
